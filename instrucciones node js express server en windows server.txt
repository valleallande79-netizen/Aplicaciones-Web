¿Por qué "excepto node_modules"?

Nunca copies esa carpeta entre máquinas — regenérala siempre con npm install. No vale la pena arrastrarla (miles de ficheros pequeños) y evita problemas si la máquina nueva tiene otra versión de Node.

OJO : Qué hace exactamente serve-index y por qué no lo necesitas (te recomendaría quitarlo, no solo por simplificar sino por seguridad.)

serve-index genera un listado navegable (tipo "índice de directorio a la antigua") cuando visitas una carpeta que no tiene index.html. Pero tu app ya no lo necesita: express.static sirve index.html automáticamente en cuanto visitas /contabilidad/ o /car-maintenance/ — eso ya funciona sin serve-index. Su única función real hoy es que si alguien visita la raíz (http://ip:8080/), ve un listado de todas tus carpetas (certs, node_modules, car-maintenance, contabilidad, etc.).

Eso último es exactamente lo que no quieres: aunque ya bloqueamos el acceso directo a los ficheros sensibles, serve-index sigue revelando que existen — cualquiera en tu red ve de un vistazo que hay una carpeta certs/, puede fisgonear nombres de ficheros, y en general es reconocimiento gratis para quien esté curioseando. Quitarlo no rompe nada de la app y reduce superficie de ataque (una dependencia npm menos que mantener, con sus propias dependencias transitivas).

Qué hace cada comando, en realidad

npm install -g pm2-windows-startup — instala un paquete npm que sabe registrar el arranque automático de PM2 en Windows (PM2 en sí no tiene esto nativo, a diferencia de Linux donde usa systemd).

pm2-startup install — esto es lo importante: crea una Tarea Programada de Windows (no un servicio de Windows) con disparador "Al iniciar sesión", cuya acción es ejecutar pm2 resurrect. Es decir: cuando inicias sesión en tu usuario de Windows, esa tarea arranca el demonio de PM2 y le dice "recupera los procesos que tenías guardados".

pm2 save — vuelca la lista de procesos que PM2 tiene corriendo en ese momento (en tu caso, server.js) a un fichero ~/.pm2/dump.pm2. Es lo que pm2 resurrect lee para saber qué relanzar.

Configurarlo correctamente (el servicio)
# Directorio de trabajo: donde vive server.js (rutas relativas del __dirname dependen de esto)
nssm set AplicacionesWebServer AppDirectory "C:\Users\Calvo\Desktop\Aplicaciones Web"

# Logs — aqui apareceran las marcas [+Xms] que ya tiene el server.js
nssm set AplicacionesWebServer AppStdout "C:\Users\Mario\Desktop\Aplicaciones Web\service-out.log"
nssm set AplicacionesWebServer AppStderr "C:\Users\Mario\Desktop\Aplicaciones Web\service-err.log"

# Rotar logs para que no crezcan sin limite (10 MB, rota online sin reiniciar el servicio)
nssm set AplicacionesWebServer AppRotateFiles 1
nssm set AplicacionesWebServer AppRotateOnline 1
nssm set AplicacionesWebServer AppRotateBytes 10485760

# Arranque automatico RETRASADO — da tiempo a que la red este lista
# antes de que el servicio intente hacer bind a 0.0.0.0 (Causa n.2 de antes)
nssm set AplicacionesWebServer Start SERVICE_DELAYED_AUTO_START

Ese retraso no es un número que configuramos nosotros directamente — es el comportamiento estándar de Windows para "Automatic (Delayed Start)", y 2-3 minutos encaja exactamente con su valor por defecto.

Qué es realmente ese retraso

SERVICE_DELAYED_AUTO_START no acepta un parámetro "espera X segundos" en el propio NSSM. Es el Service Control Manager de Windows el que decide cuándo arrancar los servicios marcados como "delayed", y por defecto ese retraso es de 120 segundos (2 minutos) tras terminar de procesar los servicios de arranque normal — a lo que hay que sumar el propio tiempo de arranque de esos servicios previos y la carga del sistema en ese momento, así que en la práctica 2-3 minutos es totalmente esperado, no un fallo.

Es justo el comportamiento que buscábamos al activarlo (evitar que intente hacer bind antes de que la red esté lista, la Causa nº2 de la que hablamos), pero es un mecanismo "a ciegas": espera un tiempo fijo, no comprueba si la red está realmente lista

# Si el proceso muere por lo que sea, que se reinicie solo
nssm set AplicacionesWebServer AppExit Default Restart
nssm set AplicacionesWebServer AppRestartDelay 5000
